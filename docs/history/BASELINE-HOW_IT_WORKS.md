# 何をどうやって取り出しているか

このページだけ読めば、mkra が何をしているかは分かります。
実装の細部と落とし穴は [ABI.md](../ABI.md) にありますが、そちらは読まなくて構いません。

---

## 1. 本体の構造

4S-C00AS1 の SoC は **ViXS XCode6**（ARM Cortex-A9 ×2、Linux 3.10.24）です。
受信系は次のように繋がっています。

```
アンテナ
  │
  ▼
Sony CXD2868ER (RF)  ──►  SC1501A (復調, ISDB-S3)
                              │
                              ▼  TLV ストリーム
                          ┌───────────────────────────────────┐
                          │  XCode6（ハードウェア処理ブロック）   │
                          │                                   │
                          │   TLV ──► MMT_DEMUX ─┬─► 映像 ES ──► 映像デコーダ ──► HDMI
                          │                      ├─► 音声 ES ──► 音声デコーダ
                          │                      └─► MMT-SI（番組情報）
                          └───────────────────────────────────┘
```

BS4K は MPEG-TS ではなく **MMT/TLV** で放送されています。本体は TLV を解いて
MMT からエレメンタリストリーム（映像・音声そのもの）を取り出し、デコーダへ渡しています。
**この時点で ACAS による復号は終わっています。**

---

## 2. mkra がすること

XCode6 には **REMUX** という「ES から MPEG-TS を組み立てるハードウェアブロック」があります。
本体はこれを**録画のときだけ**使っています。

mkra がやっているのは、**同じものをもう一つ作って、本体が動かしている映像・音声 ES に
横から繋ぐ**ことです。

```
                          MMT_DEMUX ─┬─► 映像 ES ─┬─► 映像デコーダ  （本体。そのまま動く）
                                     │            │
                                     ├─► 音声 ES ─┼─► 音声デコーダ  （本体。そのまま動く）
                                     │            │
                                     └─► MMT-SI   └─► REMUX  ◄── mkra が作る
                                                       │
                                                       ▼
                                                  MPEG-TS ──► HTTP ──► TVTest
```

これが成立するのは、**ES リングが複数の読み手を許す設計だから**です。
本体は映像に 4 枠、音声に 5 枠を確保していて、実際に使っているのは 1 枠と 2 枠。
空きがあるので、外から 1 枠もらっても本体は何も困りません。

そのため mkra は:

- **録画を必要としません**（本体の録画機能は一切使いません）
- **本体の視聴を止めません**（テレビは映ったままです）
- **復号を行いません**（もともと平文の ES を受け取っています）
- **本体が作ったものを壊しません**（触るのは自分で作った REMUX だけです）

出てくるのは 192 バイトの TTS（タイムスタンプ付き TS）なので、mkra が 4 バイトを剥がして
普通の 188 バイト MPEG-TS にしています。PAT / PMT は REMUX 自身が生成します。

---

## 3. 選局

**RF だけを別のトランスポンダに合わせても駄目です。**
本体の MMT フィルタが「今映しているサービスのアセット」向けに設定されたままなので、
周波数だけ動かすと ES リングが空になります。

なので mkra は、**本体自身のチャンネル変更要求をそのまま送ります。**
リモコンで選局したときに本体内部で流れるのと同じメッセージです。

```
System V メッセージキュー 0x36F へ、msgId 0x6004 を送る
body = [0, OID, 9, Tune, 0x0b, SID, RF_kHz, TSID, NotDecode, BID]
```

このメッセージ形式は、送信側の関数を逆アセンブルして読んだものと、
リモコンで 10 波切り替えたときのシリアルコンソールのログ 10 本が
**完全に一致した**ので確定しています。

受け取った本体は、RF を合わせ直し、MMT フィルタを組み直し、ES リングを作り直します。
つまり**本体が本来やる手順をそのまま実行する**ので、取りこぼしがありません。
所要は約 4 秒です。

成功したかどうかは、送信結果ではなく **本体が書き出す番組情報ファイル
（`/tmp/adsb/AdsbSiMhSdtActual.dat`）が新しいサービスを指したか**で判定します。

---

## 4. 今どのチャンネルを映しているかの判定

本体は受信中の MMT-SI（番組情報）を `/tmp/adsb/` にファイルとして書き出しています。
mkra はこれを**ただ読むだけ**です。ドライバにも ioctl にも触りません。

- `AdsbSiMhSdtActual.dat`（MH-SDT）→ TLV ストリーム ID とサービス ID
- `AdsbSiMpt.dat`（MPT）→ 今受信しているパッケージの ID

**この 2 つが一致したときだけ**「このサービスを映している」と判断します。
一致しない間は選局途中とみなして配信しません。

EPG（番組表）も同じディレクトリの MH-EIT から作っています。

## 5. なぜ BS/CS 2K と地上デジタルは出ないのか

同じ復調器（SC1501A）で BS/CS 2K も地上デジタルも**復調まではできます**。
BER 0 まで復調でき、TMCC から実在の TSID も返ってきます。

出ないのは、**復調器から SoC へ MPEG-TS を渡す経路**が成立しないからです。
BS4K は TLV として同じ経路を通っているので、配線自体は生きています。
しかし MPEG-TS として流したときだけ、SoC 側のデマルチプレクサが 1 バイトも受け取りません。

ソフトウェア側で試せる仮説は全て単独で試験して否定済みです。
詳細と、再開に何が必要かは [LIMITATIONS.md](../LIMITATIONS.md) にあります。

## 6. どうやって調べたか

他の機種へ移植したい人向けに、手順だけ書いておきます。

1. **シリアルコンソールを繋ぐ。** 本体は起動時から `ttyS0` 115200 にログを出しています。
   何が起きているかの一次情報はここにしかありません。
2. **ドライバのライブグラフを読む。** `/dev/kmem` と `kallsyms` から、
   ドライバが持っているオブジェクト表をたどります（`mkra graph`）。
   **ハンドルを総当たりしてはいけません**。カーネルが落ちます。
3. **本体のプロセスを逆アセンブルする。** `abs` / `adsb` / `tuner` の 3 つが
   受信系を握っています。ログ文字列から逆に参照元をたどると、
   その処理を行っている関数に着けます。
4. **実際に流れているメッセージと突き合わせる。**
   `/proc/<tid>/syscall` と `/proc/<pid>/mem` を読むと、
   本体が今送受信しているメッセージがそのまま観測できます。

**「動いたように見えて実は違う」を常に疑ってください。**
この機種では「ロックした」も「データが返ってきた」も、有効な放送データの証拠には
なりませんでした。最終的な証拠は常に「絵が出るか」「CC エラーが 0 か」です。
