# 制限事項 — 出ないもの、その理由

証拠タグ: `[S]` 静的解析 / `[M]` 実機実測 / `[I]` 推論

---

## 1. BS/CS 2K（従来の BS・CS110）は出ません

**復調までは成功しています。**

- 復調器（SC1501A）は BS/CS 2K を **BER 0 まで復調**し、TMCC から実在の TSID と
  変調方式を返します [M]
- BS-1 / TSID `0x4010` で RF PLL のロック、復調器のロックまで実測済み [M]
- 復調器の TS 出力レジスタも有効ビットが立っています（`0x0b=0x01`, `0xcc=0xc0`）[M]

**出ないのは、復調器から SoC のデマルチプレクサへ MPEG-TS が渡らないから**です。
SoC 側は 1 バイトも受け取りません。

### 試して否定したもの

ソフトウェアで検証できる仮説は、すべて**単独で試験して否定**しました。

| 仮説 | 結果 |
|---|---|
| TSI のレーン選択（TSI0 / TSI1）が違う | 両方試験。どちらも 0 バイト [M] |
| SoC の crossbar / route 設定が違う | 4K 動作中の既知良品と MMR が完全一致 [M] |
| パケット長が 188 でない（192 / 204 / 130） | 204 を試験して否定 [M] |
| SYNC ビットの扱い | 0→1 を試験して否定 [M] |
| 復調器に TLV 用の設定が残っている | 該当ビットを 1 バイトだけクリアして試験。変化なし [M] |
| 別の consumer（TS_RECODER）を使う | 生成・接続・run まで成功、8 秒間 0 バイト [M] |
| TS を消費するデバイスが無いだけ | デマルチプレクサを作って PID フィルタまで投入。0 バイト [M] |
| SoC 側の consumer 排他 | 4K 動作中に第二のデマルチプレクサを追加しても両方動く。棄却 [M] |
| CPLD のセレクタ設定 | **CPLD は非搭載**。起動ログで確定（`cpld[0]`）[M] |

ファームウェアのログまで確認したところ、PID フィルタもセクションリングも
正しく生成・有効化されていましたが、**入力側にパケットが 1 つも来ていません**でした [M]。
停止点は「復調器 → SoC の入力段」より上流に限定されます。

### 再開に必要なもの

次のいずれかが得られない限り、追加の試験を設計できません。**ソフトウェアだけでは進みません。**

1. **基板の導通確認** — 復調器の TS sync / valid が SoC まで来ているか
2. **タイミング図またはロジックアナライザの波形** — エッジ・VALID 極性を決めるもの
3. **SC1501A 世代（ISDB-S3 対応品）の production reference**

**注意**: この機種は 4K 専用 SKU です。2K の受信経路は**製品として一度も検証されていません**。
配線されていない可能性も残ります [I]。

## 2. 地上デジタルも出ません

**同じ出口を通るため、1 と同じ理由で不可**です [S]。

同調そのものは実装済みで、RF 側（CXD2868ER）のラッチ一致までは確認しています [M]。
しかし復調器のロックが成立せず、仮に成立しても 1 の TS 出口を通るため出ません。

`gr` / `gr-off` コマンドはこの調査の残骸です。

---

## 3. 同時に扱えるのは 1 チャンネルだけ

チューナーは物理的に 1 個です（`gAribTunerCnt=1`）。
地デジ・BS/CS 2K・BS4K は**同じ物理ユニットをモード切り替えして使っており**、
同時受信はできません [S][M]。

そのため:

- 裏録はできません
- 別チャンネルを要求すると `503 tuner busy with <ch>` を返します
- 選局すると**テレビの画面もそのチャンネルに変わります**

---

## 4. 実行してはいけないコマンド

`mkra --help` には調査中に使ったコマンドが多数残っています。
**以下は動きません。実行しないでください。**

| コマンド | 何が起きるか |
|---|---|
| `gr` / `gr-off` | 地デジ同調。I2C に書き込むので**実行後は再起動が必要**。ストリームは出ません |
| `demux` / `tsrec` | BS/CS 2K の TS 取り出し試験。0 バイトで終わります |
| `dmd-*` / `isdbs-*` / `sc1501a-snapshot` | 復調器のレジスタ操作・観測。一部は I2C に書き込みます |
| `cpld` | CPLD セレクタ。**この機種に CPLD は載っていません** |
| `tune` / `fed-off` / `fem-dev` | フロントエンド直叩き。4K の選局には `tune4k` を使ってください |
| `probe --scan` | **カーネルを oops させます**。ハンドル総当たりは実績があります |

**正常に使うコマンドはこれだけです。**

```sh
mkra serve --remux4k --tune --channel-type BS4K --port 40772 --epg-dir /tmp/adsb
mkra remux4k --discover-only          # read-only
mkra remux4k --out x.ts --seconds 20
mkra tune4k --sid 141                 # 単発選局
mkra graph [--sniff]                  # read-only
```

削除せず残しているのは、**否定した経路も記録として意味がある**からです。
同じ仮説を再び試す人が、実測結果を先に読めるようにしてあります。

## 5. その他の制限

| | |
|---|---|
| **待機中は配信できません** | スタンバイでは ES リングが解放されます。`--tune` 付きなら自動で起床を試みますが、**成功しない場合があります**（未解明）[M] |
| **省電力になりません** | 復号を止めても CPU idle 88.8%、発熱も体感で変わりませんでした。熱源は RF・電源・HDMI 側とみられます [M][U] |
| **チップ温度が読めません** | 温度取得 ioctl は実装しましたが全ワード 0 を返します [M] |
| **eth0 が使えない個体があります** | 実機ではリンクダウンしていました。USB WiFi は動きますが、カーネルモジュールの自前ビルドが必要です [M] |
| **`/tmp/mt` は再起動で消えます** | 意図的です。永続化の仕組みを持たないことが安全性の担保になっています |
| **`/api/programs` は `--epg-dir` が要ります** | 指定しないと空配列を返します |
| **advanced CS（ND-23）は未対応** | 本体の該当データが 2017 年の工場初期値のままで、信頼できません |

## 6. 「動いたように見える」罠

この機種で実際に何度も騙されたので、記録しておきます。
**以下はいずれも、有効な放送データが取れている証拠になりません。**

- ioctl が成功した（`Dxd_CreateRoute` にはスロット使用中なら何もせず成功を返す経路があります [S]）
- オブジェクトが生成できた
- 復調器がロックした
- **TSI がロックして CRC が進んだ** — 4K の TLV ストリームでも同じ指標が動きます [M]
- **`get_read` がデータを返した** — 物理アドレスを誤って map すると
  「それらしいゴミ」が読めます [M]
- バイト数が増えた

**証拠になるのは 2 つだけです。**

1. `ffprobe` / `ffmpeg` で**実際にフレームがデコードできる**
2. 188 バイト同期率と**連続性カウンタ（CC）エラーが 0**

`tools/deploy.py --smoke` はこの 2 つを自動で確認します。
