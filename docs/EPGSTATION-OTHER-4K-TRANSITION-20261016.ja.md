# BS2K録画後のBS4K連続予約失敗と修正

## 誤った成功判定

当初は2K→NHK BSP4Kへの試験で配信復帰を確認し、選局の照合に`AdsbSiMpt.dat`を用いた。しかし、実運用でBS日テレ4K・BS-TBS4Kの予約が失敗した。純正ADSBの実際の受信サービスは変更されていても、MPT本体・Clone・MH-SDTのファイルが以前のNHKのまま残っていた。

予約ログでは最初の503（直前ストリームの解放待ち）に続き、再試行ごとにnative/MPT identity不一致を繰り返し、録画が始まらなかった。HDMI黒画面の有無からこの問題は判断できない。

## 最終修正

`src/native_selection.rs`は検証済みadsb（MD5 `44df75ed0aa1d98ffe30239695b1e5bf`）だけで、`AdsbTumSessionStatus`（VA0x0039a3fc）の先頭64バイトを読み取る。要求は+0x10、取得済みSID/NIDは+0x30。+0x28/+0x2cのbusy値が両方0であり、要求と取得済みSID/NID・RF・TSID・BIDが一致することが必要。

要求SIDだけでは完了ではない。141→161の遷移では、要求が161へ変わっても取得済みが141の期間があった。busyが解けても旧SIDなら拒否する。テストはこの状態を合成データで再現する。

BS4K配信開始は、この取得済みサービス照合に加えて、同じ映像・音声ESリングの新しい書き込みを250ms間隔で確認し、接続直前にもう一度取得状態とOIDを照合する。固定アドレスはハッシュ・プロセス名・有効mappingが合う場合だけ使用。プロセスメモリには書き込まない。

## 実機追試

| 経路 | 結果 |
| --- | --- |
| BS日テレ2K→BS日テレ4K、予約間隔0秒 | 4K録画280,552,616バイト、format duration78.136秒。予定枠の自動終了とHEVC3840×2160/AAC-LATMの10秒デコード成功 |
| BS日テレ2K→BS-TBS4K、予約間隔0秒 | 4K録画281,538,648バイト、77.825秒。同じく自動終了・映像音声デコード成功 |
| 2K後に番組表からBS日テレ4K予約 | 114,562,312バイト、32.088秒。主映像音声の10秒デコード成功。約30秒で試験予約だけ手動終了 |
| 2K→NHK BSP4K HTTP回帰 | HTTP200、10秒35,127,296バイト、映像音声の3秒デコード成功 |
| 上記4K録画のブラウザ再生 | MP4/480p、5秒以上の映像進行、video error=null |

最初のブラウザ再生は並列のデコード検証と同時に行って60秒でタイムアウトした。直列での再実行は成功したが、負荷だけが原因とは断定しない。

単一チューナーの予約で`allowEndLack=true`を使うと、後続予約準備のため先行2K録画末尾が約15秒短縮されうる。隣接する両番組の全時間を無欠落で録画できるという意味ではない。番組表試験の途中終了を番組全編の自動終了成功とも扱わない。
